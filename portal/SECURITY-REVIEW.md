# مراجعة بوابة أمن المنشآت — 3 نوفمبر 2026

## تعليق الدخول

أظهر Auth أن محاولة حساب القائد نجحت، بينما الواجهة انتظرت تحميل الجلسة. اختبار التحكم أعاد نفس الحالة بالإصدار القديم: طلب كلمة المرور نجح وبقي الزر معطلًا خلف Web Lock ممسوك في تبويب آخر. الإصدار المثبت 2.118.0 يستخدم منسق الجلسات المحدث، وطلبات العميل لها مهلة وإلغاء ورسالة خطأ ثابتة. لا يُستخدم قفل مخصص يتجاوز حماية المكتبة، ولا يُستنتج دور المستخدم من بيانات المتصفح.

## إجراءات نُفذت

- تثبيت مكتبة المتصفح داخل الموقع، مع مصدرها وترخيصها وبصمة SHA-256، بدل طلب CDN أثناء فتح الدخول.
- مهلة تشمل جسم استجابة Auth/REST، ومنع تطبيق نتيجة تهيئة أقدم من محاولة الدخول. مهلة العملية تلغي العميل؛ إعادة المحاولة تفتح مستندًا جديدًا حتى لا تتداخل عمليات قديمة.
- إصلاح حدود أخطاء الأقسام بانتظار الوعود داخل try/catch، ومسح هوية الحساب ومحتوى العمل المحمي فور تسجيل الخروج.
- منع API المستخدمين من قراءة answers/session_id/payload_hash/client_hash في سجل النتائج، مع إبقاء أعمدة النتيجة والتسليم المصرح بها تحت RLS. صلاحية الإشعارات كانت مقيدة بعلامة read_at أصلًا، وأعيد التحقق منها.

## ما تحقق في الصلاحيات

فحص PostgreSQL داخل ROLLBACK تحقق من إرسال السرّي بكل الرتب الـ17، ومنع المرسل والمفوضين بجميع المسؤوليات السبعة من قراءته وPDF والمراجعات والإشعارات السرية، ومنع تصعيد العضويات والرتب وتزوير هوية التسليم، وإلغاء الوصول بعد سحب التفويض. عميل الموقع لا يملك الكتابة المباشرة إلى العضويات أو التقارير أو التفويضات. مخزن PDF خاص. نقطتا الاختبار والاستعادة المؤقتتان منشورتان برد ثابت 410 فقط. فحص الملفات المتتبعة لم يعثر على JWT لخدمة service_role أو مفتاح بريد فعلي.

## ملاحظات باقية وحدود المراجعة

| الموضوع | النتيجة والأثر |
|---|---|
| سرية مفاتيح إجابات الاختبارات | ملفات بنوك الأسئلة العامة تحتوي answerIndex، وcatalog في المستودع العام مشتق منها. تصحيح الخادم يمنع تزوير الدرجة المرسلة، لكنه لا يخفي الحلول. يلزم بنك اختبارات خاص ومفاتيح غير منشورة للحصول على اختبار مغلق الإجابات؛ حذف الحقول من الصفحة وحده لا يمحو تاريخ Git العام. |
| سلامة جدول Google القديم | النسخ ترسل إلى Apps Script العام دون اعتماد سري في الطلب. لا يُعد الجدول الخارجي المرجع الموثوق للنجاح؛ الوصول المباشر إلى هذا المسار لا يمر بتصحيح البوابة أو إشعاراتها. يلزم تحقق داخل Apps Script لإغلاق الإدخال من مصادر أخرى. لم يُرسل اختبار تزوير إلى الجدول الحقيقي أثناء المراجعة. |
| مطابقة نسخة Google | الرد القديم لا يعيد إيصال المحاولة. حالة النسخة غير مؤكدة حتى يعود إيصال مطابق؛ علامة التسليم واسم المنفذ في سجل الموقع فقط حاليًا. |
| البريد | إشعارات الموقع مستقلة؛ تسليم رسائل لكل عنوان مفوض لم يُختبر بإرسال فعلي. SMTP وتوثيق المرسل وحدود المزود تبقى مطلوبة للتوسع. |
| كلمات المرور المسربة | حماية HaveIBeenPwned في Supabase Auth غير مفعلة. هذا إعداد Auth لا توفر الأدوات المتصلة تغييره مباشرة. المرجع: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection |
| التحمل والاستعادة | لم تُثبت اختبارات تحمل لمئات المستخدمين أو استعادة نسخة احتياطية مستقلة. |

تنبيهات current_user_role وtouch_updated_at وcase_shares تخص تطبيقًا آخر في نفس المشروع؛ لم تُغيّر صلاحياته أو مخازنه. SECURITY DEFINER في RPC البوابة مقصود، ومقيد داخل الدوال بهوية الخادم وصلاحياتها. هذه مراجعة للمسارات المذكورة وفحوص انحدار، وليست ضمانًا لخلو كل الكود من الثغرات.

## تصحيح خاص للدورات
نصوص الخيارات بقيت عامة، وأزيلت `answerIndex` من الملفات المنشورة الست والكتالوج العام. الخادم فقط يستعيد المفاتيح من `app_private`، ويتوقف بأمان عند تعذر استرجاعها. مفاتيح النسخ السابقة باقية في تاريخ Git العام؛ يلزم بنك جديد لتغيير سرية الإجابات بالفعل.
