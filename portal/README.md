## ما تم برمجته
- واجهة عامة، تسجيل/دخول بريد وكلمة مرور عبر Supabase Auth، انتظار موافقة القائد.
- حقول الاسم داخل اللعبة ومعرف ديسكورد والرتبة من قائمة معتمدة، وكود ASF متسلسل وفريد عند التفعيل.
- لوحة القائد: قبول/رفض/إيقاف، تعديل رتبة، تفعيل خاص لمجلس القضاء، الموافقة على تعديل الاسم أو ديسكورد.
- تقارير منظمة وحرة، ومسودات، وتصحيح مرتبط بالأصل، رقم/وقت إرسال من الخادم، تحويل PDF عربي ورفع إلى bucket خاصة.
- السرية مُتحقق منها عبر Row Level Security: **secret للقائد فقط**. لا يراه المرسل بعد الإرسال ولا أي عضو مفوّض.
- مراجعات القائد وحالات التقرير وملاحظاته، الأرشيف وسلة المحذوفات والاستعادة.
- تفويض قراءة التقارير حسب النوع (باستثناء secret مطلقًا) مع نقطة توسيع لأدوات القيادات الأخرى.
- آلة مخالفات الشرطة العسكرية تستخدم بيانات الموقع القديم؛ وسجل قضائي جديد منفصل لا يمس الأرشيف السابق.
- شاشة دورات أمن المنشآت مستخرجة من قائمة الأكاديمية القائمة. **الاختبارات الحالية تفتح في الأكاديمية القديمة مؤقتًا**؛ الدمج الداخلي للاختبارات مرحلة لاحقة.
- وظائف Edge خادم لإشعار البريد وحذف التقارير وملفاتها بعد 30 يومًا **تحتاج إعداد ونشر وتشغيل مجدول**.

2. في SQL Editor شغّل بالترتيب:
   `portal/supabase/schema.sql` ثم `02-report-submission.sql` ثم `03-maintenance.sql`.
3. من Supabase Auth اضبط Site URL وRedirect URLs على عنوان GitHub Pages للبوابة، وفعّل التحقق من البريد حسب سياستك.
4. اكتب **Project URL** و**Publishable/anon key** فقط في `portal/config.js`.
5. افتح صفحة `/rass-academy/portal/` بعد دمج الفرع، وسجّل حساب القائد وتحقق من بريده. انسخ **Auth user UUID** من صفحة Authentication > Users.
6. من SQL Editor شغّل:
   ```sql
   insert into app_private.commanders(user_id) values ('AUTH_USER_UUID_HERE');
   ```
   لا تستخدم بريد القائد وحده كدليل منح الصلاحية.
7. سجّل مستخدمًا تجريبيًا، فعّله من لوحة القائد، وتأكد من توليد `ASF-000001`. جرّب التقرير العادي والسري بحسابين مختلفين.
8. وظائف البريد والكرون: ثبّت Supabase CLI (بشكل مستقل) وشغّل من مجلد `portal`:
   ```bash
   supabase functions deploy asf-notify --project-ref PROJECT_REF --no-verify-jwt
   supabase functions deploy asf-purge --project-ref PROJECT_REF --no-verify-jwt
   ```
   اضبط `RESEND_API_KEY` في Supabase Edge Functions؛ بريد القائد يُستخرج آليًا من حسابه المؤكد عبر RPC مقيدة بالخادم. اضبط `RESEND_FROM` عند توثيق نطاق الإرسال، ولا حاجة لـ`ASF_COMMANDER_EMAIL`. مفاتيح التنظيف والـservice role تبقى محصورة بالخادم.
9. بعد تركيب migration 15، لا حاجة لإضافة Webhooks يدويًا؛ اختبر رسالة فعلية بعد إعداد أسرار Resend.
10. جدولة `asf-purge`: عبر Supabase Cron/pg_cron + pg_net أو Scheduler مؤمّن، يوميًا، مع `Authorization: Bearer ASF_CRON_TOKEN`. لا تعتبر 30 يومًا تلقائية حتى ينجح اختبار المهمة.
