# بوابة أمن المنشآت — النسخة الأساسية (MVP)

## أدوات القيادات الجديدة
- `police.manage`: تعديل العقوبات المقترحة لكل مخالفة ورتبة عبر جدول overrides مستقل؛ لا يتغير كود الموقع القديم.
- `court.manage`: تصريح صريح من القائد للوصول إلى مجلس القضاء بصلاحياته المتساوية.
- `users.review`: الاطلاع على طلبات التسجيل وتعديل البيانات فقط؛ الموافقة/الإيقاف وتغيير الرتب لا تزال حصرية للقائد على مستوى الخادم.
- كل التفويضات تُعطى وتسحب حصريًا من القائد وتُسجّل في `asf_audit`.
- ملف SQL الجديد: `portal/supabase/12-leadership-tools.sql` بعد `11-pdf-finalization.sql`.
- اختُبرت الصلاحيات على قاعدة البيانات بمعاملة مؤقتة ثم ROLLBACK؛ النتائج: نجاح استخدام أدوات التفويض وفشل محاولة قبول حساب من المفوّض.


## تحديث الصلاحيات ومعالجة PDF
- تم تقييد عدد القادة المعتمدين إلى قائد واحد فقط على مستوى قاعدة البيانات.
- أضيف تفويض `reports.review` للقيادات حسب فئة التقرير، مع إمكانية حفظ الملاحظات وتغيير حالة المراجعة.
- يبقى نوع `secret` محجوبًا نهائيًا عن أي مفوّض، بصرف النظر عن التفويضات.
- إذا فشل رفع PDF لكن التقرير وصل إلى قاعدة البيانات، يستطيع القائد إعادة تكوين الملف من محتوى التقرير المؤرشف وحفظه في المسار الخاص المسجل.
- تم التحقق باستخدام معاملة SQL تجريبية (ROLLBACK) من أن المفوّض يستطيع مراجعة تقارير الأفراد ولا يستطيع قراءة أو مراجعة سري للغاية.
- لتركيب تحديث قاعدة البيانات في مشروع جديد: شغّل `portal/supabase/09-delegated-reviews-pdf-repair.sql` بعد الملفات السابقة.

مشروع رول بلاي عربي RTL، **مضاف في مجلد مستقل** للمحافظة على الأكاديمية القديمة. لم يتم استبدال الصفحة الرئيسية أو حذف سجلات قديمة.

## ما تم برمجته
- واجهة عامة، تسجيل/دخول بريد وكلمة مرور عبر Supabase Auth، انتظار موافقة القائد.
- حقول الاسم داخل اللعبة ومعرف ديسكورد والرتبة من قائمة معتمدة، وكود ASF متسلسل وفريد عند التفعيل.
- لوحة القائد: قبول/رفض/إيقاف، تعديل رتبة، تفعيل خاص لمجلس القضاء، الموافقة على تعديل الاسم أو ديسكورد.
- تقارير منظمة وحرة، ومسودات، وتصحيح مرتبط بالأصل، رقم/وقت إرسال من الخادم، تحويل PDF عربي ورفع إلى bucket خاصة.
- السرية مُتحقق منها عبر Row Level Security: **secret للقائد فقط**. لا يراه المرسل بعد الإرسال ولا أي عضو مفوّض.
- مراجعات القائد وحالات التقرير وملاحظاته، الأرشيف وسلة المحذوفات والاستعادة.
- تفويض قراءة التقارير حسب النوع (باستثناء secret مطلقًا) مع نقطة توسيع لأدوات القيادات الأخرى.
- آلة مخالفات الشرطة العسكرية تستخدم بيانات الموقع القديم؛ وسجل قضائي جديد منفصل لا يمس الأرشيف السابق.
- شاشة دورات أمن المنشآت مستخرجة من قائمة الأكاديمية القائمة. **الاختبارات الحالية تفتح في الأكاديمية القديمة مؤقتًا**؛ الدمج الداخلي للاختبارات مرحلة لاحقة.
- وظائف Edge خادم لإشعار البريد وحذف التقارير وملفاتها بعد 30 يومًا **تحتاج إعداد ونشر وتشغيل مجدول**.

## ملاحظات أمان أساسية
- GitHub Pages يعرض HTML/JS علنًا؛ لا يخزن بيانات التقارير السرية. الحماية الحقيقية في Supabase Auth + RLS + Storage private.
- لا تضع مفاتيح `service_role` أو مفاتيح البريد/الكرون أو كلمات المرور داخل `config.js` أو GitHub.
- إنشاء حساب القائد بنفسه لا يمنحه امتيازًا تلقائيًا؛ الربط يُنفذ مرة واحدة من SQL Editor باستخدام UUID الصحيح، لمنع انتحال الحساب.
- فوض فقط `reports.read` مع النوع المناسب عند الحاجة. خيار جميع الأنواع يظل يستثني «سري للغاية» بقواعد الخادم.
- لا تعتمد على إخفاء عناصر الواجهة لحماية البيانات.
- تصدير PDF حاليًا يتم في المتصفح ثم يرفع بصيغة خاصة. النص والحقول محفوظة أيضًا كسجل مرجعي في قاعدة البيانات؛ يلزم اختبار PDF العربي على الأجهزة المستهدفة.
- تحسينات الواجهة لا تعني أن الإنتاج جاهز. **لم تُشغّل الهجرات أو وظائف البريد/الجدولة على حساب Supabase من هذه المحادثة**.

## تشغيل مبدئي
1. أنشئ مشروع Supabase مخصصًا للبوابة أو اعتمد مشروعًا تملكه بعد مراجعة عزله ونسخه الاحتياطي.
2. في SQL Editor شغّل بالترتيب:
   `portal/supabase/schema.sql` ثم `02-report-submission.sql` ثم `03-maintenance.sql`.
3. من Supabase Auth اضبط Site URL وRedirect URLs على عنوان GitHub Pages للبوابة، وفعّل التحقق من البريد حسب سياستك.
4. اكتب **Project URL** و**Publishable/anon key** فقط في `portal/config.js`.
5. افتح صفحة `/rass-academy/portal/` بعد دمج الفرع، وسجّل حساب القائد وتحقق من بريده. انسخ **Auth user UUID** من صفحة Authentication > Users.
6. من SQL Editor شغّل:
   ```sql
   insert into app_private.commanders(user_id) values ('AUTH_USER_UUID_HERE');
   ```
   لا تستخدم بريد القائد وحده كدليل منح الصلاحية.
7. سجّل مستخدمًا تجريبيًا، فعّله من لوحة القائد، وتأكد من توليد `ASF-000001`. جرّب التقرير العادي والسري بحسابين مختلفين.
8. وظائف البريد والكرون: ثبّت Supabase CLI (بشكل مستقل) وشغّل من مجلد `portal`:
   ```bash
   supabase functions deploy asf-notify --project-ref PROJECT_REF --no-verify-jwt
   supabase functions deploy asf-purge --project-ref PROJECT_REF --no-verify-jwt
   ```
   اضبط Supabase Functions Secrets: `ASF_WEBHOOK_SECRET`, `RESEND_API_KEY`, `ASF_COMMANDER_EMAIL`, `RESEND_FROM`, `ASF_CRON_TOKEN`. وأضف رابط Supabase URL وservice role للـ purge كأسرار خادم (قد توفرها المنصة تلقائيًا).
9. أضف Database Webhooks للـ INSERT على `public.asf_profiles` و`public.asf_reports` إلى Function `asf-notify`، مع هيدر `x-asf-webhook-secret` يطابق سر Edge Function. تأكد من إرسال بريد تجريبي.
10. جدولة `asf-purge`: عبر Supabase Cron/pg_cron + pg_net أو Scheduler مؤمّن، يوميًا، مع `Authorization: Bearer ASF_CRON_TOKEN`. لا تعتبر 30 يومًا تلقائية حتى ينجح اختبار المهمة.

## ما يلزم قبل اعتبار الموقع منتهيًا
- اختبارات حقيقية لقواعد RLS (قائد/مرسل/مفوّض/مستخدم غير مفعل) وPDF العربي على الهواتف.
- تشغيل SMTP/Resend والبريد وخادم الحذف اليومي، والتحقق من سجلات الأخطاء.
- نقل وظائف اختبار الأكاديمية داخل البوابة بدل الرابط المؤقت، وعزل/إلغاء قطاعات غير أمن المنشآت.
- نقل واجهة الشرطة العسكرية ومجلس القضاء القديمة كأقسام داخلية متكاملة بدل الاعتماد على قائمة مخالفاتها فقط.
- تحسين UX وتدقيق صلاحيات أدوات القيادة الإضافية.
- نسخة احتياطية موثوقة من بيانات المواقع القديمة قبل أي تغيير لمسارات الإنتاج.

## ترتيب التنفيذ / أمر كودكس الواضح
1. **P0**: اختبر SQL، RLS وسرية التقارير، ولا تسمح بأي عرض للتقرير secret إلا commander؛ اكتب حالات اختبار.
2. **P0**: اربط مشروع Supabase آمن، اختبر الدخول والتفعيل ورفع PDF وقراءته مع حسابين منفصلين.
3. **P0**: شغّل بريد إشعارات التسجيل والتقارير؛ السرية بلا عنوان/محتوى البريد.
4. **P0**: فعّل الحذف النهائي بعد 30 يومًا وتحقق من إزالة كائنات Storage قبل صفوف قاعدة البيانات.
5. **P1**: انقل الأكاديمية واختباراتها للأمن المنشآت فقط مع الحفاظ على الدرجات وقواعد الإعادة، ثم نقل الشرطة العسكرية وأعمال القضاء.
6. **P1**: تدقيق صلاحيات التفويض التفصيلية وواجهات التعديل والرفض وسجل الإجراءات.
7. **P2**: الأداء، الجوال، تحسين PDF، البحث، الفلاتر، التنبيهات الحية.

مبدأ العمل: لا تُعد بناء الموجود من الصفر، ولا تُعدّل بيانات الإنتاج قبل الاختبارات والنسخ الاحتياطي، والتزم بتغيير محدود لكل مهمة.
